# Data model

Invoice Desk keeps everything in one SQLite file, `invoice_desk.sqlite`, in the data folder (see the README). The schema is defined in Dart with [drift](https://drift.simonbinder.eu/) (`lib/data/tables.dart`, triggers in `lib/data/triggers.drift`), and every released version has a snapshot in `drift_schemas/app_db/`.

## Conventions

- **IDs** are UUID v4 strings, generated on the device. They never change and are never reused, which is what a future sync engine needs.
- **Money** is an integer in minor units (hundredths): `2200000` is 22,000.00. Never a float. Rates are basis points (`1400` = 14%).
- **Dates** without a time (issue, due, signed…) are `YYYY-MM-DD` text, so they sort correctly as text. **Timestamps** (`created_at`, `updated_at`, `deleted_at`) are UTC epoch milliseconds.
- **Soft delete**: `deleted_at` set means the row is in "المحذوفات". Start-up housekeeping hard-deletes rows deleted more than 30 days ago (contracts, then invoices, then clients that no document references). Rows deleted together (a client "with all its documents") share the same `deleted_at`, which is how Undo and restore find the batch.
- **STRICT tables**: SQLite enforces column types; booleans are `INTEGER` with `CHECK (x IN (0, 1))`.
- **Foreign keys** are on (`PRAGMA foreign_keys = ON` on every open). Clients are `ON DELETE RESTRICT`, so a client with invoice or contract rows can't be hard-deleted. Children such as sections, items, clauses and milestones are `CASCADE`. A milestone's invoice link is `SET NULL`.
- **Guards** (triggers) keep live documents from pointing at a deleted client:
  - `clients_soft_delete_guard` refuses to soft-delete a client that still has live invoices or contracts.
  - `invoices_*_guard` and `contracts_*_guard` refuse to add or revive a document under a deleted client.
  - The app's "delete with all documents" path soft-deletes the documents first, in the same transaction.
- **Numbers** are unique and never reused, deleted rows included.
  - Invoices are `<prefix>-<year>-<seq:0000>`, unique on `(year, seq)`.
  - Contracts are unique on `(series, year, seq, amendment_no)`, so `CT-2026-0001`, `QT-2026-0001` and `CT-2026-0001-A1` can share a year.

## Migration history

| Version | Release | Changes |
|---|---|---|
| v1 | 0.1.0 | `settings`, `clients`, `invoices`, `sections`, `items`. Invoice soft delete. `invoices.client_id ON DELETE RESTRICT`. |
| v2 | 0.1.1 | `clients.deleted_at`. Triggers: `clients_soft_delete_guard`, `invoices_revive_guard`, `invoices_insert_guard`. |
| v3 | 0.2.0 | `clause_templates`, `library_clauses`, `contracts`, `contract_clauses`, `scope_items`, `payment_milestones`. Legal fields on `clients` and `settings`, plus contract prefixes, default jurisdiction and digit style. The client guard now counts contracts, with contract insert/revive guards. Seeds the clause library once. |

Migrations are step-by-step (`lib/data/db.steps.dart`, generated by `dart run drift_dev make-migrations`) and live in `AppDatabase._upgrade`. Each one is tested against the snapshots in `test/drift/app_db/`. Backups from older versions can still be restored: restore copies the columns both sides have, and new columns take their defaults.

```sql
CREATE TRIGGER clients_soft_delete_guard BEFORE UPDATE OF deleted_at ON clients WHEN NEW.deleted_at IS NOT NULL AND(EXISTS (SELECT 1 FROM invoices WHERE client_id = NEW.id AND deleted_at IS NULL) OR EXISTS (SELECT 1 FROM contracts WHERE client_id = NEW.id AND deleted_at IS NULL))BEGIN SELECT RAISE (ABORT, 'client has live documents');END
```
