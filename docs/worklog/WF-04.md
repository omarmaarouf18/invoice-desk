## Findings
- 2026-11-19 — Jobs in `package.yml` already read only `inputs.*`, so adding the dispatch trigger needed no job changes. `ci.yml` and `release.yml` pass both inputs explicitly, so the new dispatch defaults don't affect them.
- 2026-11-19 — No `concurrency` block was added to `package.yml`. Inside a called workflow, `github.event_name` is the **caller's** event, so a `release.yml` dry run (itself `workflow_dispatch`) would be treated as a hand run and could cancel or be cancelled.
- 2026-11-19 — **D4 ordering.** GitHub documents **Require linear history** as refusing pushed merge commits, with no exception for a fast-forward. `dev` holds one merge commit that `main` doesn't (`5dd01de`, the Phase 0 merge). So:
  - if the rule is added before Phase 3, `git push origin dev:main` is refused;
  - after it is added, any merge commit on `dev` blocks the next fast-forward.

  `RELEASING.md` now states both points. Not tried on GitHub.
